## What shipped tonight (in order)

### 1. Google sign‑in went live
Your Web client ID is wired into the app (`src/lib/auth-config.ts`) **and** the backend
(`GOOGLE_CLIENT_ID` env on Hetzner). `/v1/auth/google` now verifies tokens (returns 401 on
a bad one instead of 503). Native Google sign‑in works on the dev build.

### 2. Tab restructure
Tab bar is now **Home · Compete · Learn · Friends · Profile**.
- **Trade** tab removed; the trade sandbox moved to a standalone `/sandbox` route, still
  opened from inside a competition ("Open trade sandbox"). Trading is competition‑scoped.
- **Learn** is the new tab (details in §5).

### 3. First‑login interactive tutorial (coach‑marks)
A real spotlight system (not slides): dims the screen, cuts a **gold‑ringed hole** around
a real element, shows a tooltip with step dots / Skip / Next. Walks: **streak → daily goal
→ diamonds → start‑a‑duel → tabs**. Fires once after first login (resets on sign‑out so you
can replay). Built as a reusable kit (`features/tour/*`, `store/tour.ts`) so any future
screen can be coach‑marked with a one‑line `<TourTarget>` wrap.

### 4. Diamond economy 💎
Soft currency (`store/wallet.ts`):
- **Start 100**, **+50 daily login bonus** (celebrated after the tutorial so popups don't
  collide; idempotent so it can't double‑grant).
- **Create competition = 25**, **join = 10**. Too poor → a **Get Diamonds** sheet opens
  instead of failing.
- **Get Diamonds sheet**: **Watch a short ad → +30** (works now as an AdMob *stub*) and
  **buy packs** (₺29 / ₺59 / ₺129) marked *Coming soon* for Google Pay later.
- Diamond balance pill on Home / Compete / Profile.

### 5. Backtest challenge (the new mini‑game)
**Learn tab → Backtest challenge → Play** (free; Lessons stays premium "coming soon").
- Opens a **random instrument at a random moment** — past candles shown, future hidden.
- You pick **Long/Short** and set **Stop‑loss / Take‑profit** (± steppers, drawn as
  red/green lines on the chart).
- **Reveal** replays the hidden future candle‑by‑candle until SL or TP is hit, then shows
  the result and **awards XP** (+5 💎 on a take‑profit win). "Play again" reshuffles.
- Code: `features/backtest/engine.ts` (scenario + outcome), `app/backtest.tsx` (screen).

### 6. Fresh start for new users
New accounts open to a clean slate (`hooks/useIsFresh` + shared `ui/EmptyState`):
- No fake XP/level/streak. **Home/Compete/Friends/Profile** show friendly empty states;
  achievements all locked; greeting reads "Welcome to Arena".

### 7. Night mode 🌙
**Profile → Night mode** switch flips the whole app to a dark palette (`store/theme.ts`,
light/dark palettes in `theme/tokens.ts`). StatusBar and backgrounds follow the mode.

## Known limitations / needs human input

- **Everything new is in‑memory mock** (wallet, created competitions, tour‑seen flag,
  theme choice). They **reset on app restart**. Making them persistent needs
  `AsyncStorage` — a **native module**, so it's batched for the **next EAS rebuild**
  (along with anything else native). Not urgent for testing.
- **Ads & payments are stubs.** "Watch ad" grants instantly (no real AdMob yet); buy packs
  are disabled. Real AdMob + Google Pay are a later, native task.
- **Backtest uses generated (random‑walk) charts**, not real historical data — fine for a
  simplified practice game; we can swap to real candles later via the backend.
- **App still runs on mock data** for friends/activity/public competitions. Wiring the rest
  of the app to the live NestJS backend is the next big step.

## ⚠️ Compliance reminder (carried in code + memory)
The council's rule is **"payment never touches the leaderboard."** Diamonds *earned by
playing* gating competitions is fine. The line we must not cross when wiring **Google Pay**:
**purchased** diamonds must never buy a **cash‑prize** leaderboard placing. Keep
competitions virtual‑money / bragging‑rights only. Get a Turkish avukat's read before any
real‑money switch goes on.
